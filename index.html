Step 3: CartProvider: a private list, read-only getters

lib/providers/cart_provider.dartpart 1
class CartProvider extends ChangeNotifier {
  final List<Product> _items = []; // private: only this class changes it

  // Read-only copy for the UI. cart.items.add(...) would throw an error.
  List<Product> get items => List.unmodifiable(_items);

  int get count => _items.length;

  bool contains(Product product) {
    return _items.any((item) => item.id == product.id);
  }
_itemsis private: only this class changes it
itemswhat widgets get: a read-only copy
Debug Console
cart.items.add(p);
Unsupported operation: Cannot add to an unmodifiable list
So every change must use our methods, and we never forget notifyListeners()
any(...)asks: “is there any item with this id?”

Step 4: changing the cart

lib/providers/cart_provider.dartinside CartProvider
void add(Product product) {
  if (contains(product)) return; // each product only once
  _items.add(product);
  notifyListeners();
}

void remove(Product product) {
  _items.removeWhere((item) => item.id == product.id);
  notifyListeners();
}

void clear() {
  _items.clear();
  notifyListeners();
}
1Change the private listremoveWhere removes every item that matches the test
2Then notifyListeners()every method does both, in this order

Step 5: toggle and the total

lib/providers/cart_provider.dartinside CartProvider
void toggle(Product product) {
  if (contains(product)) {
    remove(product);
  } else {
    add(product);
  }
}

double get totalPrice {
  double total = 0;
  for (final product in _items) {
    total += product.price;
  }
  return total;
}
1toggleone method for an “Add / Remove” button
2totalPrice is a computed valuenever stored, always calculated from the list, so it can never be wrong

Big idea

Separating business logic from UI

In the provider (business logic)In widgets (UI)
What is in the cartHow a product looks (Card, Icon, Text)
Rules: each product once, add, remove, clearWhich icon or button text to show
The total priceShowing it with toStringAsFixed(2) and “LYD”
notifyListeners()context.read<CartProvider>().toggle(product)
No BuildContext, no widgetsNavigation (Navigator.push)
Bad: a for loop in CartScreen that adds up prices
Good: cart.totalPrice
Could you explain it to a shop owner without the screen? Then it goes in the provider.

Rule of thumb: if you could explain it to a shop owner without mentioning the screen (“the total is the sum of the prices”), it belongs in the provider.

Wrap-up

Summary

Today you learned

  • Model = final data; provider = private list + methods + computed values
  • List.unmodifiable: the UI can read, only the provider can change
  • MultiProvider above MaterialApp: cart and theme for every screen
  • Watch to show, read to change; every watcher updates by itself
  • Folders: models, data, providers, screens, widgets
